source files named below win over this document; update both together.

## 5. Flow map (Join / Submit / Report / Contact / Fund)

```
JOIN FELLOWSHIP
  /superintelligence/form  ──▶  GitHub account (if needed)
                             ──▶  Read FELLOW_AGREEMENT.md
                             ──▶  Discussions Introductions form  (membership record)

AIR-CRAFT SUBMISSION (before Submit)
  /protocols#workflow-air-craft-submission
  or air-craft protocols/submissions/README.md

SUBMIT TO AIR-CRAFT
  /craft or /craft/form    ──▶  Introduction (required field on Submit form)
                             ──▶  Issues Submit form (label: submission)
                             ──▶  rebuild-air-craft.yml rebuilds AIR-Craft.md
                             ──▶  /craft cards (build snapshot + live fetch)

REPORT
  Comment on submission issue (ordinary, preferred)
  and/or Issues Formal Report form (label: report)
  Workflow: /protocols#workflow-meta-evaluation-report
  or air-craft protocols/reports/README.md

CONTACT MAINTAINERS
  Footer / Privacy link  ──▶  Issues Contact form (label: contact)
  (Does NOT enter Craft catalogue)

COMMUNITY Q&A
  Discussions category: q-a

SUPPORT INTEREST (future fund)
  /superintelligence/fund  ──▶  FormEasy only
  (Not accepting funds on the site yet)
```

### Issue chooser order (air-craft, `blank_issues_enabled: false`)

1. `1-submit.yml` — Submit to AIR-Craft (label `submission`)
2. `2-report.yml` — File a Formal Report (label `report`)
3. `3-contact.yml` — Contact (label `contact`)

Maintainers may still see a Blank issue (Maintainers only).

### Catalogue rebuild pipeline

- **Workflow:** `.github/workflows/rebuild-air-craft.yml` in `air-craft` repo.
- **Triggers:** issue events, daily cron, manual.
- **Inputs:** `AIR-Craft.seed.md` + open Issues labeled `submission`.
- **Effect of closing a submission Issue:** drops that project from the list (no separate approval gate).
- **Output:** `AIR-Craft.md` (raw markdown on `main`).

### Website Craft data pipeline

- **Build time:** `scripts/sync-air-craft.mjs` writes `src/data/airCraft.generated.json` on every `bun run build` and on the daily Pages deploy.
- **Runtime:** `/craft` first paints using the build snapshot, then performs a live `fetch()` of `AIR-Craft.md` to refresh cards after mount.
- **SEO:** meta for `/craft` stays on the build snapshot until the next deploy.

### Website workflows pipeline

- **Build / dev:** `scripts/sync-workflows.mjs` writes `src/data/workflows.generated.json` (submission README + template; report README + three prompts). Prefers local sibling `../air-craft`, else raw GitHub.
- **UI:** `/protocols` Workflows section (`WorkflowsSection` + `CopyBlock`). Do not restate templates or prompts on other pages — link to `/protocols#workflow-air-craft-submission` or `/protocols#workflow-meta-evaluation-report`.

## 9. What this site is / is not

**Is**
Public narrative and entry points for AIR: framework overview, infrastructure (Guides, Routes), Protocols and Lab tools, AIR-Craft portfolio, Fellowship join, Fund interest registration, and GitHub-native contact.

**Is not**
- The full research corpus (desktop product architecture, kernel docs) — those live in other `docs/` files and external repos.
- A grants portal. The Fund form registers interest only; no money is accepted on the site.
- An admissions pipeline. Joining is open enrollment via a Discussions introduction.
- A bug tracker for the website itself. Website bugs go to `gyrogovernance/gyrogovernance.com`, not to `air-craft`.

### Hard rules for any model editing this codebase

1. Do not invent pages, routes, products, "Assignments" programs, or claims beyond this outline. If a feature is not in `src/router.tsx`, it does not exist.
2. Do not change canonical lines (Section 4) without explicit instruction.
3. Do not change the Issue Form order or labels.
4. Do not add a FormEasy form to `/craft/form` or `/superintelligence/form`. They hand off to GitHub.
5. When adding a new page: update `router.tsx`, `src/lib/seo.ts`, `src/lib/nav.ts` (if navigable), and add a Section 6 entry here.
6. When changing copy that appears on multiple surfaces (e.g., the voluntary contribution sentence), update every file listed in the Sources of Truth table.
7. Craft project cards always read from `src/lib/airCraft.ts`. Never hard-code a project card in `Craft.tsx`.
8. The Human Mark body lives in `HumanMarkDropdown.tsx`. If the canonical `THM.md` changes, mirror it there.

### Website naming vs protocol READMEs

On the website, prefer full names over the THM acronym in navigation and workflows:

Do not use on site UI chrome: Self-Audit, Orientation (as a Fellowship step), THM Classification, or Meta-Evaluation outside the Meta-Evaluation Report workflow. Do not add editorial asides such as "(THM exact)".
